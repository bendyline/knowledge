# Software update

This article is about software updates in general. For the discontinued macOS component, see [Apple Software Update](https://en.wikipedia.org/wiki/Apple_Software_Update).

**Software update** is the process of changing installed [software](https://en.wikipedia.org/wiki/Software) with the intent to make it more modern. It also refers to the [stored data](https://en.wikipedia.org/wiki/Data_storage) used to update software. When storage was significantly more expensive, [patching](https://en.wikipedia.org/wiki/Patch_\(computing\)) files was the dominant form of update. With the advent of larger distribution storage media and higher Internet bandwidth, it became common to replace entire files instead of patching.

An update may require prior application of other updates, or may require prior or concurrent updates to multiple components. To facilitate updates, operating systems often provide automatic or semi-automatic updating facilities. [Package management systems](https://en.wikipedia.org/wiki/Package_management_system) and [app stores](https://en.wikipedia.org/wiki/App_store) can offer update automation.

An update can be any size. An update can be relatively large when the changes add or replace data such as [graphics](https://en.wikipedia.org/wiki/Computer_graphics) and sound files, for example for a [game](https://en.wikipedia.org/wiki/Computer_game) update. An update usually takes less time to run than an initial installation of the software.

Although often intended to [upgrade](https://en.wikipedia.org/wiki/Upgrade), an update may instead degrade. An update may include unintentional [regression](https://en.wikipedia.org/wiki/Software_regression) problems. In some cases, an update intentionally disables functionality, for instance, by removing aspects for which the consumer is no longer licensed.

## Management



A [Sparkle](https://en.wikipedia.org/wiki/Sparkle_\(software\)) software update prompt on macOS

See also: [Category\:Software update managers](https://en.wikipedia.org/wiki/Category\:Software_update_managers), [Push technology](https://en.wikipedia.org/wiki/Push_technology), [Pull technology](https://en.wikipedia.org/wiki/Pull_technology), and [Software verification](https://en.wikipedia.org/wiki/Software_verification)

Software update systems allow for updates to be managed by users and software developers. In the [2017 Petya cyberpandemic](https://en.wikipedia.org/wiki/Petya_\(malware\)), the financial software "MeDoc"'s update system is said to have been compromised to spread [malware](https://en.wikipedia.org/wiki/Malware) via its updates.[^cite_note-1][^cite_note-2] On the Tor Blog, cybersecurity expert Mike Perry states that [deterministic](https://en.wikipedia.org/wiki/Deterministic_compilation), distributed builds are likely the only way to defend against malware that attacks the software development and [build](https://en.wikipedia.org/wiki/Software_build) processes to infect millions of machines in a single, officially signed, instantaneous update.[^cite_note-3] Update managers also allow for security updates to be applied quickly and widely. Update managers of [Linux](https://en.wikipedia.org/wiki/Linux) such as [Synaptic](https://en.wikipedia.org/wiki/Synaptic_\(software\)) allow users to update all software installed on their machine. Applications like Synaptic use cryptographic checksums to verify source/local files before they are applied to ensure fidelity against malware.[^cite_note-4][^cite_note-5]

Automatic updating has become more widespread over time. Some cite a cause of its prevalence to be due to [Windows](https://en.wikipedia.org/wiki/Windows) support in early 2000s. [Service Pack 2 of Windows XP](https://en.wikipedia.org/wiki/Windows_XP#Service_Pack_2) (available in 2004) enabled it by default.

## Classification

Updates are classified many ways. Notable classifications in alphabetical order follow.

### Hotfix

This section is an excerpt from [Hotfix](https://en.wikipedia.org/wiki/Hotfix).\[[edit](https://en.wikipedia.org/w/index.php?title=Hotfix\&action=edit)]

A [hotfix](https://en.wikipedia.org/wiki/Hotfix) is a software update that is released outside the normal update cycle or intended to be applied to a live system, often to fix a [bug](https://en.wikipedia.org/wiki/Software_bug).[^cite_note-6]

Originally, *hotfix* referred to [patching](https://en.wikipedia.org/wiki/Patch_\(computing\)) a *hot* system – a production [server](https://en.wikipedia.org/wiki/Server_\(computing\)) that is actively serving [clients](https://en.wikipedia.org/wiki/Client_\(computing\)). For development, such a change usually must be designed quickly and outside normal development processes, at relatively high cost and at the expense of other development effort. For the user, a hotfix is relatively risky since it is applied to a server without time for testing it. The risk of applying the hotfix must be weighed against the risk of *not* applying it. The problem to be fixed might be so critical that inaction is riskier than the potential loss of service.

Over time, the meaning has shifted to an update that is created with urgency or released outside the normal update cycle for the software.

Applying (installing) a hotfix generally involves the same process as any software update. Most modern [operating systems](https://en.wikipedia.org/wiki/Operating_systems) and desktop [applications](454746.md) can download and apply updates automatically. [Network administrators](https://en.wikipedia.org/wiki/Network_administrators) may use software programs to automate and simplify applying updates to the machines they manage.

### Malicious update

Cybercriminals can use a number of methods to send fake software updates which include malware. Methods to distribute this type of malicious software include emails and pop-up windows.[^cite_note-7] A report by the [American Civil Liberties Union](https://en.wikipedia.org/wiki/American_Civil_Liberties_Union) has suggested that state actors have attempted to include code, for surveillance purposes, in software updates sourced from legitimate companies and software developers, traditionally considered to be safe and reliable.[^cite_note-8][^cite_note-9]

### Patch

This section is an excerpt from [Patch (computing)](https://en.wikipedia.org/wiki/Patch_\(computing\)).\[[edit](https://en.wikipedia.org/w/index.php?title=Patch_\(computing\)\&action=edit)]

A [patch](https://en.wikipedia.org/wiki/Patch_\(computing\)) is [data](https://en.wikipedia.org/wiki/Data) for modifying an existing [software resource](https://en.wikipedia.org/wiki/System_resource) such as a [program](https://en.wikipedia.org/wiki/Computer_program) or a [file](https://en.wikipedia.org/wiki/Computer_file), often to fix [bugs](https://en.wikipedia.org/wiki/Software_bug) and [security vulnerabilities](https://en.wikipedia.org/wiki/Security_vulnerability).[^cite_note-10][^cite_note-11] To *patch* is also the process of applying the data to the existing resource. Patching a system involves applying a patch. A patch may be created to improve functionality, [usability](https://en.wikipedia.org/wiki/Usability), or [performance](https://en.wikipedia.org/wiki/Computer_performance). A patch may be created manually, but commonly it is created via a tool that compares two versions of the resource and generates data that can be used to transform one to the other.

Typically, a patch needs to be applied to the specific version of the resource it is intended to modify, although there are exceptions. Some patching tools can detect the version of the existing resource and apply the appropriate patch, even if it supports multiple versions. As more patches are released, their cumulative size can grow significantly, sometimes exceeding the size of the resource itself. To manage this, the number of supported versions may be limited, or a complete copy of the resource might be provided instead.

Patching allows for modifying a [binary](https://en.wikipedia.org/wiki/Machine_language) [executable](https://en.wikipedia.org/wiki/Executable). Although this can be technically challenging (requires a thorough understanding of the workings of the executable), it may be feasible when the [source code](https://en.wikipedia.org/wiki/Source_code) is unavailable to [build](https://en.wikipedia.org/wiki/Software_build) a full executable, and it allows for a smaller distribution which can be more economical than distributing full files.

Although often intended to fix problems, a patch can introduce new problems – a scenario called [software regression](https://en.wikipedia.org/wiki/Software_regression). In some cases, an update intentionally disables functionality, for instance, by removing aspects for which the consumer is no longer licensed. [Patch management](https://en.wikipedia.org/wiki/Patch_management) is a part of [lifecycle management](https://en.wikipedia.org/wiki/Application_lifecycle_management), and involves a strategy and planning of what patches should be applied to which systems and at what times. Typically, a patch is applied in a permanent way (i.e. to [storage](https://en.wikipedia.org/wiki/Computer_storage)), but in some cases, a patch is applied to memory (i.e. via a tool such as a [debugger](https://en.wikipedia.org/wiki/Debugger)) in which case the change is lost when the resource is reloaded from storage.

Software update is sometimes conflated with patch even though they are not [synonyms](https://en.wikipedia.org/wiki/Synonym). An update can be implemented using patch files and the patching process. Also, some may contend that patching is not limited to modifying file content – that adding, removing and replacing whole files is patching. Typically, patch connotates a relatively small change, so a patch that is large in size or scope may be called the more general *software update* or another more specific name such as [service pack](https://en.wikipedia.org/wiki/Service_pack). [Windows NT](https://en.wikipedia.org/wiki/Windows_NT) and its successors (including [Windows 2000](https://en.wikipedia.org/wiki/Windows_2000), [Windows XP](https://en.wikipedia.org/wiki/Windows_XP), [Windows Vista](https://en.wikipedia.org/wiki/Windows_Vista) and [Windows 7](https://en.wikipedia.org/wiki/Windows_7)) use *service pack*.[^cite_note-12] Historically, [IBM](https://en.wikipedia.org/wiki/IBM) used the terms *FixPak* and *Corrective Service Diskette* for such updates.[^cite_note-13]

### Patch release

This section is an excerpt from [Patch release](https://en.wikipedia.org/wiki/Patch_release).\[[edit](https://en.wikipedia.org/w/index.php?title=Patch_release\&action=edit)]

A software versioning diagram

Point releases are the off-white boxes in the diagram.

A [patch release](https://en.wikipedia.org/wiki/Patch_release) (also known as point release, dot release, or bugfix release) is a [release](https://en.wikipedia.org/wiki/Software_release) of [software](https://en.wikipedia.org/wiki/Software), especially one intended to fix [bugs](https://en.wikipedia.org/wiki/Software_bug) or for relatively small changes rather than add significant [features](https://en.wikipedia.org/wiki/Feature_\(software_design\)). Often, there are too many bugs to be fixed in a single major or minor release, creating a need for a point release.

### Program temporary fix

This section is an excerpt from [Program temporary fix](https://en.wikipedia.org/wiki/Program_temporary_fix).\[[edit](https://en.wikipedia.org/w/index.php?title=Program_temporary_fix\&action=edit)]

In IBM terminology, a [program temporary fix](https://en.wikipedia.org/wiki/Program_temporary_fix) or product temporary fix (PTF) is a software fix, or a group of fixes, distributed in a form ready to install.[^cite_note-14][^cite_note-15]

A PTF normally follows an [Authorized Program Analysis Report](https://en.wikipedia.org/wiki/Authorized_Program_Analysis_Report) (APAR).[^cite_note-16] When an APAR fix is issued, the PTF is generally a tested APAR fix, or a set of APAR fixes.[^cite_note-Program_temporary_fix_Gabe-17] However, if an APAR is resolved as "Fixed If Next" or "Permanent Restriction", there may be no PTF for the current release, only a correction in a later release.

PTFs are used across multiple IBM platforms and are installed using platform-specific service tools. On [IBM i](https://en.wikipedia.org/wiki/IBM_i), PTFs can be applied either temporarily or permanently, with temporarily applied fixes remaining reversible until they are made permanent.[^cite_note-18] IBM i also distributes fixes in aggregated forms such as cumulative PTF packages and PTF groups.[^cite_note-19][^cite_note-20] On [z/OS](https://en.wikipedia.org/wiki/Z/OS), PTFs are commonly installed and tracked using [System Modification Program/Extended](https://en.wikipedia.org/wiki/System_Modification_Program/Extended) (SMP/E).[^cite_note-21] On [z/VM](https://en.wikipedia.org/wiki/Z/VM), VMSES/E provides an installation and service toolset used for servicing software levels, including corrective service delivered as PTFs.[^cite_note-22]

### Security patch

A *security patch* is a change to correct the weakness described by a vulnerability. The corrective action prevents successful exploitation and removes or mitigates a threat's capability to exploit a specific vulnerability. Patch management is a part of [vulnerability management](https://en.wikipedia.org/wiki/Vulnerability_management) –  the cyclical practice of identifying, classifying, remediating, and mitigating vulnerabilities.

Security patches are the primary method of fixing security vulnerabilities in software. Currently Microsoft releases its security patches once a month ("[patch Tuesday](https://en.wikipedia.org/wiki/Patch_Tuesday)"), and other operating systems and software projects have security teams dedicated to releasing the most reliable software patches as soon after a vulnerability announcement as possible. Security patches are closely tied to [responsible disclosure](https://en.wikipedia.org/wiki/Responsible_disclosure).

These security patches are critical to ensure that business process does not get affected. In 2017, companies were struck by a ransomware called [WannaCry](https://en.wikipedia.org/wiki/WannaCry_ransomware_attack) which encrypts files in certain versions of [Microsoft Windows](18890.md) and demands a ransom via BitCoin. In response to this, Microsoft released a patch which stops the ransomware from running.

### Service pack

This section is an excerpt from [Service pack](https://en.wikipedia.org/wiki/Service_pack).\[[edit](https://en.wikipedia.org/w/index.php?title=Service_pack\&action=edit)]

In computing, a [service pack](https://en.wikipedia.org/wiki/Service_pack) comprises a collection of updates, fixes, or enhancements to a [software program](https://en.wikipedia.org/wiki/Computer_program) delivered in the form of a single installable package. Companies often release a service pack when the number of individual [patches](https://en.wikipedia.org/wiki/Patch_\(computing\)) to a given program reaches a certain (arbitrary) limit, or the software release has shown to be stabilized with a limited number of remaining issues based on users' feedback and [bug reports](https://en.wikipedia.org/wiki/Bug_tracking_system). In large software applications such as office suites, operating systems, database software, or network management, it is not uncommon to have a service pack issued within the first year or two of a product's release. Installing a service pack is easier and less error-prone than installing many individual patches, even more so when updating multiple computers over a network, where service packs are common.&#x20;

Service packs are usually numbered, and thus shortly referred to as SP1, SP2, SP3 etc.[^cite_note-23] They may also bring, besides [bug](https://en.wikipedia.org/wiki/Software_bug) fixes,[^cite_note-24] entirely new features, as is the case of [SP2](https://en.wikipedia.org/wiki/Windows_XP#Service_Pack_2) of [Windows XP](https://en.wikipedia.org/wiki/Windows_XP) (e.g. [Windows Security Center](https://en.wikipedia.org/wiki/Security_and_Maintenance#Windows_XP_SP2)), or SP3 and SP4 of the heavily database dependent *[Trainz 2009: World Builder Edition](https://en.wikipedia.org/wiki/Trainz#Trainz_Simulator_2009:_World_Builder_Edition)*.[^cite_note-25]

### Unofficial patch

This section is an excerpt from [Unofficial patch](https://en.wikipedia.org/wiki/Unofficial_patch).\[[edit](https://en.wikipedia.org/w/index.php?title=Unofficial_patch\&action=edit)]

An [unofficial patch](https://en.wikipedia.org/wiki/Unofficial_patch), a.k.a. community patch and fan patch, is a software update created by a third party, such as a [user community](https://en.wikipedia.org/wiki/User_community), without the involvement of whoever is considered the official maintainer of the [software](https://en.wikipedia.org/wiki/Software) (i.e. original developer). An unofficial patch generally does not change the intended use of the software, in contrast to other third-party adaptions such as [mods](https://en.wikipedia.org/wiki/Mod_\(video_gaming\)) or [cracks](https://en.wikipedia.org/wiki/Software_cracking).

An unofficial patch is typically intended to repair bugs and provide new capabilities such as support for newer [operating systems](https://en.wikipedia.org/wiki/Operating_system), increased [display](https://en.wikipedia.org/wiki/Computer_display) resolutions and new display formats.[^cite_note-Unofficial_patch_cnc95-26][^cite_note-Unofficial_patch_DPresolutionfix-27] While unofficial patches are most common for the PC platform, they can also be found for console games e.g. in context of the emulation community.[^cite_note-28]

A [fan translation](https://en.wikipedia.org/wiki/Fan_translation_\(video_gaming\)) is an unofficial patch that adds natural language support to software.[^cite_note-Unofficial_patch_moo3-29] Fan translations are most common for [Japanese role-playing games](https://en.wikipedia.org/wiki/Japanese_role-playing_game) which are often not localized for Western markets.[^cite_note-Unofficial_patch_ClydeMandelin-30][^cite_note-Unofficial_patch_retrogamer-31]

A [slipstream](https://en.wikipedia.org/wiki/Slipstream_\(computing\)) like patch combines multiple official patches into one unofficial update package as a convenience to users when individual patches are only available online or as small incremental updates.

A common motivation for creating an unofficial patch is lack of [technical support](https://en.wikipedia.org/wiki/Technical_support) from the official maintainer which may result from:&#x20;

- The software reached the maintainer's defined [end-of-life](https://en.wikipedia.org/wiki/End-of-life_\(product\))

- The software was [superseded by a successor product](https://en.wikipedia.org/wiki/Planned_obsolescence)

  [^cite_note-Unofficial_patch_obsolescence-33]

- The software was originally designed to operate in a substantially different environment and may require [improvement/optimization](https://en.wikipedia.org/wiki/Porting)

- The maintainer went out of business

- Support is not economically viable (e.g. localization for small markets)

- A fast solution for a time critical problem (e.g. [security holes](https://en.wikipedia.org/wiki/Vulnerability_\(computing\))) when an official one takes too long

### Video game patch

A [video game](5363.md) receives an update (often called a patch) to fix problems and to change features such as change game rules and [algorithms](775.md). These updates may be prompted by the discovery of [exploits](https://en.wikipedia.org/wiki/Exploit_\(online_gaming\)) in the [multiplayer](https://en.wikipedia.org/wiki/Multiplayer_video_game) game experience that can be used to gain unfair advantages over other players. Extra features and gameplay tweaks can often be added. These kinds of updates are common in [first-person shooters](https://en.wikipedia.org/wiki/First-person_shooters) with [multiplayer](https://en.wikipedia.org/wiki/Multiplayer_video_game) capability, and in [MMORPGs](https://en.wikipedia.org/wiki/MMORPG), which are typically very complex with large amounts of content, almost always rely heavily on updates following the initial release, where updates sometimes add new content and abilities available to players. Because the balance and fairness for all players of an MMORPG can be severely corrupted within a short amount of time by an exploit, servers of an MMORPG are sometimes taken down with short notice to apply a critical fix.

Companies sometimes release games knowing that they have bugs. *[Computer Gaming World](https://en.wikipedia.org/wiki/Computer_Gaming_World)*'s [Scorpia](https://en.wikipedia.org/wiki/Scorpia_\(journalist\)) in 1994 denounced "companies—too numerous to mention—who release shoddy product knowing they can get by with patches and upgrades, and who make '*pay*-testers of their customers".[^cite_note-cgw199404-39]

## Process



The firmware of a Fuji Instax Liplay being updated

Software update processes vary dramatically. Some notable processes are described here.

### Firmware update

Updating [firmware](https://en.wikipedia.org/wiki/Firmware) (i.e. [motherboard](https://en.wikipedia.org/wiki/Motherboard) [BIOS](https://en.wikipedia.org/wiki/BIOS)) can be challenging when it involves replacing the entire image on the hardware. As such, an error or interruption during the update process, such as loss of power, may render the hardware unusable.&#x20;

An update, a binary image, is often installed via a supplier-provided program that overwrite the existing image with another. This program may safeguard against serious damage. For example, the update procedure could make and keep a backup of the firmware in case it determines that the primary copy is corrupt (i.e. via a [checksum](https://en.wikipedia.org/wiki/Checksum)).

### Limited release

In the cases of large updates or of significant changes, distributors often limit availability of updates to qualified developers as a [beta test](https://en.wikipedia.org/wiki/Development_stage#Beta).

### Hot patching

**Hot patching**, also known as *live patching* or [dynamic software updating](https://en.wikipedia.org/wiki/Dynamic_software_updating), is the application of software changes without shutting down and restarting the system or the program concerned. This addresses problems related to unavailability of service provided by the system or the program.[^cite_note-40] This method can be used to update the [Linux kernel](https://en.wikipedia.org/wiki/Linux_kernel) without stopping the system.[^cite_note-41][^cite_note-42]

A patch that can be applied in this way is called a *hot patch* or a *live patch* and is a common practice in mobile apps.[^cite_note-43] Companies such as [Rollout.io](https://en.wikipedia.org/wiki/Rollout.io) use [method swizzling](https://en.wikipedia.org/wiki/Method_swizzling) to deliver hot patches to the iOS ecosystem.[^cite_note-44] Another method for hot-patching iOS apps is JSPatch.[^cite_note-45]

Cloud providers often use hot patching to avoid downtime for customers when updating underlying infrastructure.[^cite_note-46]

### Slipstreaming

*Slipstreaming* is the act of integrating updates into the [installation](https://en.wikipedia.org/wiki/Installation_\(computer_programs\)) files of their original app, so that the result allows a direct installation of the updated app.[^cite_note-47][^cite_note-48]

The nature of slipstreaming means that it involves an initial outlay of time and work, but can save a lot of time (and, by extension, money) in the long term. This is especially significant for administrators that are tasked with managing a large number of computers, where typical practice for installing an operating system on each computer would be to use the original media and then update each computer after the installation was complete. This would take a lot more time than starting with a more up-to-date (slipstreamed) source, and needing to download and install the few updates not included in the slipstreamed source.

However, not all updates can be applied in this fashion and one disadvantage is that if it is discovered that a certain update is responsible for later problems, that update cannot be removed without using an original, non-slipstreamed installation source.
