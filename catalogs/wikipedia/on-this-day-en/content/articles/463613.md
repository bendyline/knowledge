# Configuration file

"rc file" redirects here. For resource scripts, see [Resource (Windows)](https://en.wikipedia.org/wiki/Resource_\(Windows\)).

A **configuration file**, also known as **config file**, is a [file](https://en.wikipedia.org/wiki/Computer_file) that stores [data](https://en.wikipedia.org/wiki/Computer_data) used to configure a [software system](https://en.wikipedia.org/wiki/Software_system) such as an [application](454746.md), a [server](https://en.wikipedia.org/wiki/Server_\(computing\)) or an [operating system](https://en.wikipedia.org/wiki/Operating_system).

Some applications provide a tool to create, modify, and verify the [syntax](https://en.wikipedia.org/wiki/Syntax) of their configuration files – sometimes via [graphical user interface](https://en.wikipedia.org/wiki/Graphical_user_interface) (GUI). For context, [system administrators](https://en.wikipedia.org/wiki/System_administrator) may be expected to create and modify [text](https://en.wikipedia.org/wiki/Plain_text) config files via a text editor. For server processes and operating-system settings, there is often no standard tool, but operating systems may provide graphical interfaces such as [YaST](https://en.wikipedia.org/wiki/YaST) or debconf.

Some computer programs only read their configuration files at [startup](https://en.wikipedia.org/wiki/Booting). Others periodically check the configuration files for changes. Users can instruct some programs to re-read the configuration files and apply the changes to the current process, or indeed to read arbitrary files as a configuration file. There are no definitive standards or strong conventions.

## File format

In general, a config file can have any [format](https://en.wikipedia.org/wiki/File_format). The format that applies to a particular system is determined by the design of that system. Often, a standardized format is used since it allows for using tools designed for the format even if not designed for the consuming system. In particular, general-purpose [serialization](https://en.wikipedia.org/wiki/Serialization) formats, such as [JSON](https://en.wikipedia.org/wiki/JSON), [XML](https://en.wikipedia.org/wiki/XML), and [YAML](https://en.wikipedia.org/wiki/YAML), are often used in [open-source](https://en.wikipedia.org/wiki/Open-source_software) and [platform-neutral](https://en.wikipedia.org/wiki/Cross-platform) software. The [specifications](https://en.wikipedia.org/wiki/Specification) for these formats are generally publicly available to support wide-spread use.

The following table compares notable formats used for configuration data.

| Format | Formal spec | Allows [comments](https://en.wikipedia.org/wiki/Comment_\(computer_programming\)) | Syntax typing |
| --- | --- | --- | --- |
| [INI](https://en.wikipedia.org/wiki/INI_file) | No | Yes | No |
| [JSON](https://en.wikipedia.org/wiki/JSON) | Yes[^cite_note-2] | No | Yes |
| [TOML](https://en.wikipedia.org/wiki/TOML) | Yes[^cite_note-3] | Yes | Yes |
| [UCL](https://github.com/vstakhov/libucl) | No[^cite_note-4] | Yes | Yes |
| [YAML](https://en.wikipedia.org/wiki/YAML) | Yes[^cite_note-5] | Yes | Yes |
| [XML](https://en.wikipedia.org/wiki/XML) | Yes[^cite_note-6] | Yes | No |

The *syntax typing* column indicates whether the [syntax](https://en.wikipedia.org/wiki/Syntax_\(programming_languages\)) supports [data types](https://en.wikipedia.org/wiki/Data_type). A format has syntax-typing if a value's type is specified by syntax – e.g. `true` is a [Boolean](https://en.wikipedia.org/wiki/Boolean_data_type) while `"true"` is a [string](https://en.wikipedia.org/wiki/String_\(computer_science\)). A format does not have syntax-typing if a value's type is based on [semantics](https://en.wikipedia.org/wiki/Semantics_\(computer_science\)) – e.g. `true` and `"true"` are both Boolean if the parser expects a Boolean. Opinions on the value of syntax-typing [vary](https://hitchdev.com/strictyaml/why-not/toml/#4-syntax-typing).

## Examples

The following are examples of config files organized by the [operating systems](https://en.wikipedia.org/wiki/Operating_system) on which they are commonly used.

### Unix and Unix-like

Many different file formats are used on [Unix](https://en.wikipedia.org/wiki/Unix) and [Unix-like](https://en.wikipedia.org/wiki/Unix-like) operating systems. Even so, there is a strong tradition of using human-editable, plain text formats including simple [key–value pair](https://en.wikipedia.org/wiki/Key%E2%80%93value_pair). Filename extensions of `.cnf`, `.conf`, `.cfg`, `.cf` or `.ini` are often used.

Many formats allow [comments](https://en.wikipedia.org/wiki/Comment_\(computer_programming\)), in which case, individual settings can be disabled by [prepending with the comment character](https://en.wikipedia.org/wiki/Comment_out). Often the default configuration files contain extensive internal documentation in the form of comments[^cite_note-\:0-7][^cite_note-\:1-8] and [man files](https://en.wikipedia.org/wiki/Man_file) are also typically used to document the format and options available.

System-wide software often uses configuration files stored in `/etc`, while user applications often use a "[dotfile](https://en.wikipedia.org/wiki/Dotfile)" – a file or directory in the home directory prefixed with a [period](https://en.wikipedia.org/wiki/Full_stop), which [in Unix hides the file or directory](https://en.wikipedia.org/wiki/Hidden_file_and_hidden_directory#Unix_and_Unix-like_environments) from casual listing. Since this causes pollution, newer user applications generally make their own folder in the `.config` directory, a standardized subdirectory of the home directory.

Similar to config files, a [run command](https://en.wikipedia.org/wiki/RUNCOM) (rc) [shell script](https://en.wikipedia.org/wiki/Shell_script) can configure a [shell](https://en.wikipedia.org/wiki/Shell_\(computing\)) session. Often, such scripts are named with an `rc` suffix after the consuming program's name such as `.xinitrc`, `.vimrc`, `.bashrc`, `xsane.rc`.[^cite_note-autogenerated1-9]

By contrast, [IBM](https://en.wikipedia.org/wiki/IBM)'s [AIX](https://en.wikipedia.org/wiki/AIX) uses an [Object Data Manager](https://en.wikipedia.org/wiki/Object_Data_Manager) (ODM) database to store much of its system settings.

### MS-DOS

[MS-DOS](https://en.wikipedia.org/wiki/MS-DOS) primarily relied on the `CONFIG.SYS` config file, a plain text file with simple key–value pairs (e.g. `DEVICEHIGH=C:\DOS\ANSI.SYS`). MS-DOS 6 introduced the INI-file format. Similar to an rc file, the [batch file](https://en.wikipedia.org/wiki/Batch_file) named `AUTOEXEC.BAT` ran commands on [startup](https://en.wikipedia.org/wiki/Booting). Both these files were retained up to [Windows 98SE](https://en.wikipedia.org/wiki/Windows_98SE), which still ran on top of MS-DOS.

An example CONFIG.SYS:

```
DOS=HIGH,UMB
DEVICE=C:\DOS\HIMEM.SYS
DEVICE=C:\DOS\EMM386.EXE RAM
DEVICEHIGH=C:\DOS\ANSI.SYS
FILES=30
SHELL=C:\DOS\COMMAND.COM C:\DOS /E:512 /P
```

DOS applications used a wide variety of individual configuration files, most of them binary, proprietary and undocumented - and there were no common conventions or formats.

### Windows



The REGEDIT application being used to edit Windows Registry data

Early [Windows](https://en.wikipedia.org/wiki/Windows) operating systems heavily utilized plain-text [INI files](https://en.wikipedia.org/wiki/INI_file) which served as the primary mechanism to configure the operating system and applications.[^cite_note-10] The [APIs](https://en.wikipedia.org/wiki/API) to read and write from these still exist in Windows, but after 1993, Microsoft began to steer developers away from using INI files and toward storing settings in the [registry](https://en.wikipedia.org/wiki/Windows_Registry), a hierarchical database to store configuration settings, which was introduced with [Windows NT](https://en.wikipedia.org/wiki/Windows_NT). Later systems use XML and other formats instead of the registry.

### macOS

The [Property List](https://en.wikipedia.org/wiki/Property_List) is the standard configuration file format in [macOS](https://en.wikipedia.org/wiki/MacOS) (as well as in [iOS](https://en.wikipedia.org/wiki/IOS), [NeXTSTEP](https://en.wikipedia.org/wiki/NeXTSTEP), [GNUstep](https://en.wikipedia.org/wiki/GNUstep) and [Cocoa](https://en.wikipedia.org/wiki/Cocoa_\(API\)) applications). It uses the [filename extension](https://en.wikipedia.org/wiki/Filename_extension) `.plist`.

### IBM OS/2

IBM's [OS/2](https://en.wikipedia.org/wiki/OS/2) uses a binary format, also with a .INI suffix, but this differs from the Windows versions. It contains a [list](https://en.wikipedia.org/wiki/List_\(data_structure\)) of lists of untyped key–value pairs.[^cite_note-voice-11] Two files control system-wide settings: OS2.INI and OS2SYS.INI. Application developers can choose whether to use them or to create a specific file for their applications.

### HarmonyOS and OpenHarmony operating systems

[HarmonyOS](https://en.wikipedia.org/wiki/HarmonyOS) and [OpenHarmony](https://en.wikipedia.org/wiki/OpenHarmony)-based operating systems use JSON config files, named `config.json`. The platform [IDE](https://en.wikipedia.org/wiki/Integrated_development_environment), [DevEco Studio](https://en.wikipedia.org/wiki/DevEco_Studio), provides methods for editing `config.json`.[^cite_note-12]
