# CA2022: Avoid inexact read with Stream.Read

| Property | Value |
| --- | --- |
| **Rule ID** | CA2022 |
| **Title** | Avoid inexact read with Stream.Read |
| **Category** | [Reliability](reliability-warnings.md) |
| **Fix is breaking or non-breaking** | Non-breaking |
| **Enabled by default in .NET 10** | As warning |
| **Applicable languages** | C# and Visual Basic |

## Cause

A call to [System.IO.Stream.Read*](https://learn.microsoft.com/search/?terms=System.IO.Stream.Read*) or [System.IO.Stream.ReadAsync*](https://learn.microsoft.com/search/?terms=System.IO.Stream.ReadAsync*) is made and the return value isn't checked.

## Rule description

[System.IO.Stream.Read*](https://learn.microsoft.com/search/?terms=System.IO.Stream.Read*) and [System.IO.Stream.ReadAsync*](https://learn.microsoft.com/search/?terms=System.IO.Stream.ReadAsync*) might return fewer bytes than requested, resulting in unreliable code if the return value isn't checked.

## How to fix violations

To fix a violation, either check the return value (which is the total number of bytes read into the buffer) or call [System.IO.Stream.ReadExactly*](https://learn.microsoft.com/search/?terms=System.IO.Stream.ReadExactly*) or [System.IO.Stream.ReadExactlyAsync*](https://learn.microsoft.com/search/?terms=System.IO.Stream.ReadExactlyAsync*) instead.

## When to suppress warnings

You shouldn't suppress warnings from this rule, as your app might hang if you don't fix the violations.
