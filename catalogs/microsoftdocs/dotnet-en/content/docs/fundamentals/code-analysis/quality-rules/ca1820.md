# CA1820: Test for empty strings using string length

| Property | Value |
| --- | --- |
| **Rule ID** | CA1820 |
| **Title** | Test for empty strings using string length |
| **Category** | [Performance](performance-warnings.md) |
| **Fix is breaking or non-breaking** | Non-breaking |
| **Enabled by default in .NET 10** | No |
| **Applicable languages** | C# and Visual Basic |

## Cause

A string is compared to the empty string by using [System.Object.Equals*](https://learn.microsoft.com/search/?terms=System.Object.Equals*).

## Rule description

Comparing strings using the [System.String.Length](https://learn.microsoft.com/search/?terms=System.String.Length) property or the [System.String.IsNullOrEmpty*](https://learn.microsoft.com/search/?terms=System.String.IsNullOrEmpty*) method is faster than using [System.Object.Equals*](https://learn.microsoft.com/search/?terms=System.Object.Equals*). This is because [System.Object.Equals*](https://learn.microsoft.com/search/?terms=System.Object.Equals*) executes significantly more CIL instructions than either [System.String.IsNullOrEmpty*](https://learn.microsoft.com/search/?terms=System.String.IsNullOrEmpty*) or the number of instructions executed to retrieve the [System.String.Length](https://learn.microsoft.com/search/?terms=System.String.Length) property value and compare it to zero.

For null strings, [System.Object.Equals*](https://learn.microsoft.com/search/?terms=System.Object.Equals*) and `<string>.Length == 0` behave differently. If you try to get the value of the [System.String.Length](https://learn.microsoft.com/search/?terms=System.String.Length) property on a null string, the common language runtime throws a [System.NullReferenceException](https://learn.microsoft.com/search/?terms=System.NullReferenceException). If you perform a comparison between a null string and the empty string, the common language runtime does not throw an exception and returns `false`. Testing for null does not significantly affect the relative performance of these two approaches. When targeting .NET Framework 2.0 or later, use the [System.String.IsNullOrEmpty*](https://learn.microsoft.com/search/?terms=System.String.IsNullOrEmpty*) method. Otherwise, use the [System.String.Length](https://learn.microsoft.com/search/?terms=System.String.Length) == 0 comparison whenever possible.

## How to fix violations

To fix a violation of this rule, change the comparison to use the [System.String.IsNullOrEmpty*](https://learn.microsoft.com/search/?terms=System.String.IsNullOrEmpty*) method.

## When to suppress warnings

It's safe to suppress a warning from this rule if performance is not an issue.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable CA1820
// The code that's violating the rule is on this line.
#pragma warning restore CA1820
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](../configuration-files.md).

```ini
[*.{cs,vb}]
dotnet_diagnostic.CA1820.severity = none
```

For more information, see [How to suppress code analysis warnings](../suppress-warnings.md).
