# CA1863: Use 'CompositeFormat'

| Property | Value |
| --- | --- |
| **Rule ID** | CA1863 |
| **Title** | Use `CompositeFormat` |
| **Category** | [Performance](performance-warnings.md) |
| **Fix is breaking or non-breaking** | Non-breaking |
| **Enabled by default in .NET 10** | No |
| **Applicable languages** | C# and Visual Basic |

## Cause

Code calls [System.String.Format(System.String,System.Object\[\])](https://learn.microsoft.com/search/?terms=System.String.Format(System.String%2CSystem.Object%5B%5D)) or [System.Text.StringBuilder.AppendFormat(System.String,System.Object\[\])](https://learn.microsoft.com/search/?terms=System.Text.StringBuilder.AppendFormat(System.String%2CSystem.Object%5B%5D)) with a `static` format string that hasn't been cached to a [System.Text.CompositeFormat](https://learn.microsoft.com/search/?terms=System.Text.CompositeFormat) instance.

## Rule description

It's expensive to parse a format string at runtime. This rule locates places in your code where you can cache and use a [System.Text.CompositeFormat](https://learn.microsoft.com/search/?terms=System.Text.CompositeFormat) instance as the argument to a formatting operation, rather than passing in the original format string. A [System.Text.CompositeFormat](https://learn.microsoft.com/search/?terms=System.Text.CompositeFormat) instance parses the composite format string when it's created, which means the "hot path" of string formatting can execute much faster.

## How to fix violations

Create an instance of [System.Text.CompositeFormat](https://learn.microsoft.com/search/?terms=System.Text.CompositeFormat) by calling [System.Text.CompositeFormat.Parse(System.String)](https://learn.microsoft.com/search/?terms=System.Text.CompositeFormat.Parse(System.String)) and pass it to [System.String.Format(System.IFormatProvider,System.Text.CompositeFormat,System.Object\[\])](https://learn.microsoft.com/search/?terms=System.String.Format(System.IFormatProvider%2CSystem.Text.CompositeFormat%2CSystem.Object%5B%5D)) or [System.Text.StringBuilder.AppendFormat(System.IFormatProvider,System.Text.CompositeFormat,System.Object\[\])](https://learn.microsoft.com/search/?terms=System.Text.StringBuilder.AppendFormat(System.IFormatProvider%2CSystem.Text.CompositeFormat%2CSystem.Object%5B%5D)) instead of the original format string.

## Example

The following example shows two violations of the rule:

```csharp
class C
{
    private static readonly string StaticField = "Format one value: {0}";

    static void Main()
    {
        _ = string.Format(StaticField, 42);

        StringBuilder sb = new();
        sb.AppendFormat(StaticField, 42);
    }
}
```

The following example shows code that fixes both violations:

```csharp
class C
{
    private static readonly CompositeFormat StaticField = CompositeFormat.Parse("Format one value: {0}");

    static void Main()
    {
        _ = string.Format(null, StaticField, 42);

        StringBuilder sb = new();
        sb.AppendFormat(null, StaticField, 42);
    }
}
```

## When to suppress warnings

It's safe to suppress diagnostics from this rule if performance isn't a concern.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable CA1863
// The code that's violating the rule is on this line.
#pragma warning restore CA1863
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](../configuration-files.md).

```ini
[*.{cs,vb}]
dotnet_diagnostic.CA1863.severity = none
```

For more information, see [How to suppress code analysis warnings](../suppress-warnings.md).
