- Use a secure serializer instead, and **don't allow an attacker to specify an arbitrary type to deserialize**. For more information see the [Preferred alternatives](../../../standard/serialization/binaryformatter-security-guide.md#preferred-alternatives).
- Make the serialized data tamper-proof. After serialization, cryptographically sign the serialized data. Before deserialization, validate the cryptographic signature. Protect the cryptographic key from being disclosed and design for key rotations.

Implement a custom [System.Runtime.Serialization.SerializationBinder](https://learn.microsoft.com/search/?terms=System.Runtime.Serialization.SerializationBinder). Before deserializing, set the `Binder` property to an instance of your custom [System.Runtime.Serialization.SerializationBinder](https://learn.microsoft.com/search/?terms=System.Runtime.Serialization.SerializationBinder) in all code paths. In the overridden [System.Runtime.Serialization.SerializationBinder.BindToType*](https://learn.microsoft.com/search/?terms=System.Runtime.Serialization.SerializationBinder.BindToType*) method, if the type is unexpected, throw an exception to stop deserialization.
