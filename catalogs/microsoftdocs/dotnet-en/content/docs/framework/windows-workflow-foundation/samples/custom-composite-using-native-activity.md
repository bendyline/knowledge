# Custom Composite using Native Activity

The [CustomCompositeNativeActivity sample](https://github.com/dotnet/samples/tree/main/framework/windows-workflow-foundation/basic/CustomActivities/Code-Bodied/CustomCompositeNativeActivity/CS) demonstrates how to write a [System.Activities.NativeActivity](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivity) that schedules other [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) objects to control the flow of a workflow's execution. This sample uses two common control flows, Sequence and While, to demonstrate how to do this.

## Sample Details

 Starting with `MySequence`, the first thing to notice is that it derives from [System.Activities.NativeActivity](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivity). [System.Activities.NativeActivity](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivity) is the [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) object that exposes the full breadth of the workflow runtime through the [System.Activities.NativeActivityContext](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext) passed to the `Execute` method.

 `MySequence` exposes a public collection of [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) objects that gets populated by the workflow author. Before the workflow is executed, the workflow runtime calls the [System.Activities.Activity.CacheMetadata*](https://learn.microsoft.com/search/?terms=System.Activities.Activity.CacheMetadata*) method on each activity in a workflow. During this process, the runtime establishes parent-child relationships for data scoping and lifetime management. The default implementation of the [System.Activities.Activity.CacheMetadata*](https://learn.microsoft.com/search/?terms=System.Activities.Activity.CacheMetadata*) method uses the [System.ComponentModel.TypeDescriptor](https://learn.microsoft.com/search/?terms=System.ComponentModel.TypeDescriptor) instance class for the `MySequence` activity to add any public property of type [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) or [System.Collections.IEnumerable](https://learn.microsoft.com/search/?terms=System.Collections.IEnumerable)\<[System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity)> as children of the `MySequence` activity.

 Whenever an activity exposes a public collection of child activities, it is likely those child activities share state. It is a best practice for the parent activity, in this case `MySequence`, to also expose a collection of variables through which the child activities can accomplish this. Like child activities, the [System.Activities.Activity.CacheMetadata*](https://learn.microsoft.com/search/?terms=System.Activities.Activity.CacheMetadata*) method adds public properties of type [System.Activities.Variable](https://learn.microsoft.com/search/?terms=System.Activities.Variable) or [System.Collections.IEnumerable](https://learn.microsoft.com/search/?terms=System.Collections.IEnumerable)\<[System.Activities.Variable](https://learn.microsoft.com/search/?terms=System.Activities.Variable)> as variables associated with the `MySequence` activity.

 Besides the public variables, which are manipulated by the children of `MySequence`, `MySequence` must also keep track of where it is in the execution of its children. It uses a private variable, `currentIndex`, to accomplish this. This variable is registered as part of the `MySequence` environment by adding a call to the [System.Activities.NativeActivityMetadata.AddImplementationVariable*](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityMetadata.AddImplementationVariable*) method within the `MySequence` activity's [System.Activities.Activity.CacheMetadata*](https://learn.microsoft.com/search/?terms=System.Activities.Activity.CacheMetadata*) method. The [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) objects added to the `MySequence` `Activities` collection cannot access variables added this way.

 When `MySequence` is executed by the runtime, the runtime calls its [System.Activities.NativeActivity.Execute*](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivity.Execute*) method, passing in an [System.Activities.NativeActivityContext](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext). The [System.Activities.NativeActivityContext](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext) is the activity's proxy back into the runtime for dereferencing arguments and variables as well as scheduling other [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) objects, or `ActivityDelegates`. `MySequence` uses an `InternalExecute` method to encapsulate the logic of scheduling the first child and all subsequent children in a single method. It starts by dereferencing the `currentIndex`. If it is equal to the count in the `Activities` collection, then the sequence is finished, the activity returns without scheduling any work and the runtime moves it into the [System.Activities.ActivityInstanceState.Closed](https://learn.microsoft.com/search/?terms=System.Activities.ActivityInstanceState.Closed) state. If the `currentIndex` is less than the count of activities, the next child is obtained from the `Activities` collection and `MySequence` calls [System.Activities.NativeActivityContext.ScheduleActivity*](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext.ScheduleActivity*), passing in the child to be scheduled and a [System.Activities.CompletionCallback](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback) that points at the `InternalExecute` method. Finally, the `currentIndex` is incremented and control is yielded back to the runtime. As long as an instance of `MySequence` has a child [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) object scheduled, the runtime considers it to be in the Executing state.

 When the child activity completes, the [System.Activities.CompletionCallback](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback) is executed. The loop continues from the top. Like `Execute`, a [System.Activities.CompletionCallback](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback) takes an [System.Activities.NativeActivityContext](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext), giving the implementer access to the runtime.

 `MyWhile` differs from `MySequence` in that it schedules a single [System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) object repeatedly, and in that it uses a [System.Activities.Activity`1](https://learn.microsoft.com/search/?terms=System.Activities.Activity%601)<bool\> named `Condition` to determine whether this scheduling should occur. Like `MySequence`, `MyWhile` uses an `InternalExecute` method to centralize its scheduling logic. It schedules the `Condition`[System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity)<bool\> with a [System.Activities.CompletionCallback`1](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback%601)\<bool> named `OnEvaluationCompleted`. When the execution of `Condition` is completed, its result becomes available through this [System.Activities.CompletionCallback](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback) in a strongly typed parameter named `result`. If `true`, `MyWhile` calls  [System.Activities.NativeActivityContext.ScheduleActivity*](https://learn.microsoft.com/search/?terms=System.Activities.NativeActivityContext.ScheduleActivity*), passing in the `Body`[System.Activities.Activity](https://learn.microsoft.com/search/?terms=System.Activities.Activity) object and `InternalExecute` as the [System.Activities.CompletionCallback](https://learn.microsoft.com/search/?terms=System.Activities.CompletionCallback). When the execution of `Body` completes, `Condition` gets scheduled again in `InternalExecute`, starting the loop over again. When the `Condition` returns `false`, an instance of `MyWhile` gives control back to the runtime without scheduling the `Body` and the runtime moves it to the [System.Activities.ActivityInstanceState.Closed](https://learn.microsoft.com/search/?terms=System.Activities.ActivityInstanceState.Closed) state.
